# client-solidjs

A proof: is the web client clearer in Solid 2 (RC)? At `/solid`, open or start a thread, pick its recipients, read streaming replies and tool calls, fork a message, or stop its agents. Forks sit side by side with links both ways. Runner cards choose the model and thinking level, show each agent's work, and connect to its threads with live wires. A thread's title opens its people, family and tools in either layout. Bots have their homes, instructions and recipes; memory opens from its lines down to whole messages. The walkthrough has the page's prose, try buttons and connection-line flow. Switch to just the chat for the runner list. The old client remains at `/`; cutover and serving the diagram dependency locally are still ahead. No build step: tagged templates from `@solidjs/html`, and server.js serves Solid's own files from node_modules through the import map in index.html.

    pnpm install       # at the repo root; this is a workspace package
    node server.js     # then open http://localhost:3000/solid

One file per thing, named with client.html's words: `server.js` keeps the lists live over /ws; each `thread.js` owns its message subscription and releases its shared entries when it leaves the screen, and `composer.js` keeps the draft and recipients as you move between threads. `system.js` names the connections; `wires.js` follows their endpoints through layout and scrolling. `agent-memory.js` scopes reads to the visible thread, so clearing it also discards outstanding results. `tutorial.js` connects the static page to the same server and recipients. The stylesheet is apps/client/client.css.
